- **Defect:** `pdca signoff <id> --iterate-do|--iterate-plan|… --delta "<text>"` writes `<text>` verbatim into §9's `- Iteration delta (if iterating):` field: `cli._signoff` passes `args.delta` straight through (`template/src/pdca_harness/cli.py:1473-1474`) and `signoff.record` writes it as given (`template/src/pdca_harness/signoff.py:247`, `:307-308`). NEEDS-HUMAN` heading (`signoff._needs_human_section`, `signoff.py:103-118`), and its docstring relies on §9 being single-line ("§9 holds only the sign-off record, whose iteration delta the flow flattens to one line"). A multi-line `--delta` holding a `## 6. NEEDS-HUMAN` line (e.g. a §6 block pasted from an older SUMMARY) therefore becomes the "real" §6. At the iterate transition `driver._retire_cleared_deferrals` (`template/src/pdca_harness/driver.py:135`, `:317-340`) calls `autoiterate.retire_cleared` (`template/src/pdca_harness/autoiterate.py:348`), which reads ticks from that forged block (`autoiterate.py:409-410`) and retires deferred-ledger entries the human never cleared. NEEDS-HUMAN (from v1)\n- [x] E1\n- [x] E2')"` → both retired (`kept: []`). The suite cannot see it because its helper `_section6` (`template/tests/test_autoiterate.py:95-99`) uses the same last-heading rule.
