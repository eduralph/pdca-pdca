- **Slug:** plan-advisory-tick-survives-iterate-do
- **Defect:** Plan-advisory findings are folded into SUMMARY §6 on every Check: `assemble.collect_needs_human` re-reads every `plan-advisory-*.md` in the bundle (`template/src/pdca_harness/assemble.py:446-448`) and renders each finding as an open `- [ ]` row. On iterate-do those files are NOT archived (`driver._archive_iteration` moves `plan-advisory-*` only when `include_brief` is true, i.e. on iterate-plan: `template/src/pdca_harness/driver.py:460-464`), so the next round reads the same files and every plan finding comes back unticked. The human's tick is never carried: `driver._retire_cleared_deferrals` (`driver.py:317-340`) only touches the #409 deferred-findings ledger and returns at once when that ledger is empty (`driver.py:332-333`), and even with a ledger a tick on a row that is one of this Check's own findings "retires nothing" (`autoiterate.retire_cleared`, `template/src/pdca_harness/autoiterate.py:366-370`). Effect, seen on issue_409 (5 plan findings re-cleared at each of 4 rounds) and issue_408 (6 findings across 3 rounds) of eduralph/pdca-pdca: the human clears the same plan findings again every round, even after a re-plan addressed them.
- **Success criterion:** With the patch, a plan-advisory finding the human ticked (`- [x]`) in §6 of round N's SUMMARY.md, followed by an iterate-do (`driver.advance` on a bundle whose §9 records `iterate-do`), does NOT appear as an open `- [ ]` row in §6 of round N+1's SUMMARY.md, and still does not after a SECOND iterate-do (round N+1 → N+2) with no new tick. The tick persists across rounds; it is not read once from round N's SUMMARY and then lost. The carried finding is either absent from §6 or shown outside §6's checkbox list; assembly never renders it as `- [x]` (see Scope). In the same test: (i) a plan-advisory finding the human did NOT tick at round N is still an open `- [ ]` row at round N+1 and N+2 and still blocks accept (`flow.accept_blockers` / `signoff.open_needs_human` returns it); (ii) after an iterate-plan, a re-plan whose plan advisory writes a `plan-advisory-*.md` raising the SAME text (byte-identical is allowed; the stub leaf does exactly that) shows it as an open row again. What resets the tick is the event, not the file content: the iterate-plan archive (`driver.py:460-464`) or a plan-advisory re-run (`leaves.py:4341-4342`). (iii) Ledger present: the same finding was also written to the #409 deferred-findings ledger by an earlier auto-iterate round (plan findings are HUMAN-kind, `assemble.py:442-445`, so `autoiterate.deferrable` keeps them, `autoiterate.py:318-325`). The human ticks it, iterate-do runs, and at round N+1 it is not an open row, neither as a fresh finding nor through `_deferred_needs_human` (`assemble.py:571-598`). Pre-fix the ticked row comes back open at round N+1. That is the RED.
- **Falsifiability:** RED is reachable offline in the template suite: a stub-config bundle with a `plan-advisory-x.md` holding one `- NEEDS-HUMAN —` finding, assembled, ticked in §6, signed off `iterate-do`, advanced and re-assembled. Pre-fix the row is `- [ ]` again (the file is re-read and nothing carries the tick). The C4 gate (`./engine/scripts/run-verify.sh`) reverts the production hunks and re-runs the named test, so the red leg runs on the same fixture. No host, network or `gh` is needed.
- **Invariant to restore:** A §6 row the human positively cleared stays cleared across a rebuild until the evidence that raised it is replaced. Only new evidence (a re-run of the leaf that raises it, even with the same text) may reopen it, and a row the human never ticked must still block accept (C6). The reset is an event (iterate-plan, or a plan-advisory re-run), not a change in file bytes, because a re-run that raises the same text is new evidence. Source: the harness's own §6 contract, `assemble.py:436-445` ("each finding stays visible until the human dispositions it at sign-off") and `autoiterate.py:351-353` ("Without it an entry the human adjudicated re-enters §6 unticked at the next assembly and blocks accept again — every round, with no way to clear it"), which already holds for deferred findings but not for plan findings.
