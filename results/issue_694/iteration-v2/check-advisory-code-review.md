- NEEDS-HUMAN [impl] — `template/src/pdca_harness/integrate.py:613-617` vs `:627`: `_clash` runs on the line as the *first* pass that skipped the id leaves it. That runs before `_hold_work` may take merged bundles off the line and restart the pass. The carry then advises "rebuild issue_X on a base that holds issue_Y" when no line holds `issue_Y`. That is the case `test_a_finished_id_held_as_well_is_never_named` (`template/tests/test_flow_reissue_after_conflict_hold.py:216`) says must not happen, though that test only covers a partner that was itself skipped, not one later held. A possible fix: after the loop, drop from each `clashes[n]` any partner in `holds` (or re-run `_clash` once on the final line), and add a test where the partner is built on a skipped id.
- `template/src/pdca_harness/flow.py:1177`: `partners` is filled for every clash, including ids in `holds`, while `why` leaves those out at `:1176`. This does no harm today, because the `built_on` hint has no `{partners}` placeholder. Still, matching `:1176` (`if name not in holds`) would keep the two maps in step.
- `template/src/pdca_harness/integrate.py:1179` (inside `_clash`) and `:1199` (`_own_work`): `_own_work` runs once per conflicting id. Each call re-walks every other bundle's commits and does an `_in_line` check for each pair, so cost grows with the square of the batch size in git calls. Batches are small, so this is cheap in practice. The walks do not depend on the conflicting id, apart from leaving it out, so they could be done once per pass in `fold` and passed in.
- `template/src/pdca_harness/integrate.py:614`: `if clashes is not None` inside the loop is dead. `conflicting` is only filled when `clashes is not None` (`:598-600`). Hoist the check, or drop it.
