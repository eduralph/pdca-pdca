- **Slug:** carry-keeps-a-fold-time-skip-off-the-line
- **Defect:** The pre-wave carry (`flow._carry_finished`, `template/src/pdca_harness/flow.py:1032-1130`) spreads "not clean" along `Depends on` edges only for ids judged not clean **before** the fold (`_cascade_not_clean`, `flow.py:1002-1029`, called at `:1093`). An id can also fail **during** the fold: `integrate.fold` with `skipped=` records a merge failure for that one bundle and goes on to the next (`template/src/pdca_harness/integrate.py:532-539`). The carry learns of it only after the fold has merged and pushed (`flow.py:1104-1113`). So a finished `Q` merged in the same fold whose branch holds commits of `P` puts them on the line, although `P` itself was skipped. The docs and docstring state this as a known residual (`docs/07-crosscutting.md:728-730`; `flow.py:1052-1054`).
  A textual conflict of `P` alone usually does not leak: a `Q` that contains `P`'s conflicting change conflicts the same way and is skipped too. It leaks when `Q` holds `P` commits but not the conflicting one, or resolved it. Shapes reproduced with plain git at Plan, each leaking on main: (a) `Q` cut from `fix/P`, then `fix/Q` updated from a base that conflicts with `P` and resolved, `P` not updated; (b) `Q` cut from `P`'s first commit `p1`, then `P` adds `p2` that conflicts with the base, folded in the order `Q, P` (Q merges with `p1`, then `P` fails); (c) an earlier integration line `L` holds `p1`, `P` is rebuilt on `L` with a conflicting `p2`, `Q` is built on `L`, `L` is gone, the fold starts fresh: `P` fails, `Q` merges with `p1`.

- **Invariant to restore:** The pre-wave carry never puts onto the line it pushes the work of an id its own fold skipped, directly or through another finished bundle's branch. **Definition (fixed; not Do's to refine):** for a finished id `P` the carry's fold skips, *`P`'s work* is every commit reachable from either of `P`'s heads — `heads[P]`, the PR head the carry already holds from `gh` (`flow.py:1076-1088`), and `fix/P`'s tip in the carry's clone when that branch resolves (the fold does not expose the head it read, and for a gone branch it read none, `integrate.py:520`, `:619-620`) — that is reachable from neither `origin/<base>` nor the commit the fold started the line from (the base on a fresh line, origin's line tip on a continued one). Merge commits count. A commit `P` shares with another branch counts as `P`'s work whoever wrote it; nothing else is exempt (not a recorded stack base, not a `Depends on` prerequisite's history). The invariant: no commit of any skipped id's work is reachable from the tip the carry pushes, and the carry pushes each target at most once. A finished id whose tip reaches any of a skipped id's work is not carried; it is held, with that skipped id named as its cause, and so are its plain `Depends on` dependents. Holds may be conservative (see out of scope); leaks may not. "Skipped" means any id the fold records in `skipped=`, whatever the error: a conflict, a non-conflict `git merge` failure (`integrate.py:632-635`) or a gone-branch error from `_gone_branch` (`:659-686`) — criterion (7) pins a non-conflict one. Scoped to fold-time skips in the carry; the pre-fold cascade and the red re-gate are out of scope. Source: the carry contract, "Only a clean prerequisite is carried" (`docs/07-crosscutting.md:718`), and the invariant #652 stated and left half-covered (residual at `docs/07-crosscutting.md:728-730`). Self-test: handling only the declared `Depends on` edge, only one fold order, or only a fresh line would not satisfy it; criteria (2), (3), (4) pin that.
