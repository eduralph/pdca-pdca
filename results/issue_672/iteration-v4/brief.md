- **Slug:** carry-keeps-a-fold-time-skip-off-the-line
- **Defect:** The pre-wave carry (`flow._carry_finished`, `template/src/pdca_harness/flow.py:1032-1130`) spreads "not clean" along `Depends on` edges only for ids judged not clean **before** the fold (`_cascade_not_clean`, `flow.py:1002-1029`, called at `:1093`). An id can also fail **during** the fold: `integrate.fold` with `skipped=` records a merge failure for that one bundle and goes on to the next (`template/src/pdca_harness/integrate.py:532-539`). The carry learns of it only after the fold has merged and pushed (`flow.py:1104-1113`). So a finished `Q` merged later in the same fold, whose branch holds `P`'s commits, puts `P`'s work on the line even though `P` itself was skipped. The docs and docstring state this as a known residual (`docs/07-crosscutting.md:728-730`; `flow.py:1052-1054`).
  A textual conflict of `P` alone does not leak: `Q` contains `P`'s change, so it conflicts the same way and is skipped too (checked with git at Plan). It leaks when `Q`'s branch already resolved that conflict. The realistic shape, also checked with git at Plan: `P` and `Q` (branch cut from `fix/P`) are finished with open PRs; the base then gets a change that conflicts with `P`; `Q`'s author updates `fix/Q` from the base and resolves the conflict, `P`'s author does not. The carry's fold starts from the base, `P` conflicts and is skipped, `Q` merges cleanly, and `P`'s commit is on the line.
