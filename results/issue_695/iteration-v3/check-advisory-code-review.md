# Advisory code review — issue 695

I found no correctness bugs that block this patch. Every case the brief names has a test. The two round-2 problems are fixed: each target and each branch is now judged on its own (`template/src/pdca_harness/integrate.py:770-791`), and the tests cover a failing target sorted both before and after the one with the rewrite, plus a failing ancestry check next to a rewrite. All gates pass (T3: 2525 tests OK). What's left is small.

- NEEDS-HUMAN [impl] — `template/src/pdca_harness/flow.py:2723-2727`: the "could not check … by hand" line copies the raw `IntegrationError` text into `({why})`. That text was written for an in-fold failure, so it gives the wrong advice at the end of a run. `_fetch`'s text says "the fold cannot see the branches it merges" (`integrate.py:1545-1546`). `_in_line`'s text says "check that checkout, then re-run" (`integrate.py:1186-1188`). Re-running is not the fix here, because the run already pushed its line. Suggested fix: pass only the short cause (e.g. "could not fetch origin in <repo>", "`git merge-base --is-ancestor` exited 128"), or drop the remedy part of the text. Exit code and detection are correct; this is wording only.
- `template/tests/test_integrate_carried_rewrite_late.py:623-691, 798-816`: none of the tests patch `integrate._FETCH_RETRY_PAUSE` (`integrate.py:1519`), so every case that fails a fetch sleeps a real second. That is about 5 s across the file for nothing. `mock.patch.object(integrate, "_FETCH_RETRY_PAUSE", 0)` in the two `setUp`s would remove it. Speed only.
- `template/src/pdca_harness/flow.py:2716-2717` vs `integrate.py:766-767`: `_report_late_rewrites` filters `accepted` by `d.name in carried`, and `rewritten_carried` checks the same thing again. It's harmless; one of the two filters can go.
- Reuse is good. `_carried_rewrite` (`integrate.py:730-744`) is now the one place both checks get their rewrite judgment and message from. The retry lives in `_fetch` behind a keyword-only `attempts` that defaults to 1, so no other caller changes, which matches the brief's "retry no other git step". The exit-1 signal goes through 693's `holds` collector (`cli.py:695-731`) rather than a second channel. Writing the late reasons last (`flow.py:2696`) makes a rewrite win over a hold on the same id.
