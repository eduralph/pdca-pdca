# Advisory code review — issue 695

No correctness bug found in the main paths. The end-of-run check runs only in stack mode with real publishing, is skipped after a fold error or a red re-gate (`line_stopped`), and runs after Act as the brief asks. A deleted branch reads as `tip is None` and is skipped. The `"rewritten"` reason outranks a hold both in `cli._results_rc` and in the order `holds` is filled. The fetch retry fails closed after the second try, and only `_carried_tips` asks for it (all other `_fetch` callers keep `attempts=1`). I re-ran no gates. The frozen gate logs show C4 red→green and T3 green. The findings below are a scope question, one missing test, and small cleanups.

- NEEDS-HUMAN [human] — `template/src/pdca_harness/flow.py:2716` and `template/src/pdca_harness/cli.py:696`: the patch adds a reason the brief did not ask for, `"unchecked"`. If the end-of-run check itself fails (for example, its fetch fails twice), every carried bundle is marked `"unchecked"` and the run exits 1, even though every bundle is COMPLETE and no rewrite was seen. This fails closed and fits the invariant ("never ends reporting success while…"), but it also means a network hiccup after a fully successful run now turns exit 0 into exit 1. The other choice is a warning on stderr with exit 0 or 3. A human should decide which is wanted, since automation reads this exit code.
- NEEDS-HUMAN [impl] — `template/tests/test_integrate_carried_rewrite_late.py`: no test covers the `"unchecked"` path (`flow.py:2713-2717`). Nothing checks that a failing end-of-run fetch prints the "could not check … by hand" line and exits 1, or that it does not also print a rewrite line. One case would cover it: a `_git` spy that fails every fetch only after the last fold has pushed.
- `template/src/pdca_harness/flow.py:2684-2686`: the guard `do_publish and cfg.wave_mode != "merge" and cfg.publisher.mode != "stub"` is the same expression already stored in `hold_unmerged` at `flow.py:2485`. Reusing it (or a shared name such as `folds_run`) would keep the two from drifting apart.
- `template/src/pdca_harness/flow.py:2711` and `template/src/pdca_harness/integrate.py:758`: the list is filtered by `d.name in carried` twice, once by the caller and again inside `rewritten_carried`. Either one is enough. Dropping the caller's filter is simplest.
- `template/src/pdca_harness/integrate.py:1511` and `template/tests/test_integrate_carried_rewrite_late.py:272,280`: both fetch-retry tests sleep for the real `_FETCH_RETRY_PAUSE` (1 s each), and any future test that hits a failing carried fetch pays the same cost. Patching the pause to 0 in `CarriedFetchRetry.setUp` (`mock.patch.object(integrate, "_FETCH_RETRY_PAUSE", 0, create=True)`, which still loads with the fix reverted) would keep the suite fast. Minor.
- `template/src/pdca_harness/integrate.py:45-50` (module docstring) and `docs/07-crosscutting.md:683`: the reflowed text leaves a short line ("A branch deleted after its PR merged is judged by") and an over-long one ("PR merges and its branch is deleted, the fold looks up…"). Cosmetic only; the docs gates pass.
