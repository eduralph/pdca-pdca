Verdict: within the brief's scope I could not refute the fix. The red→green evidence holds, the tests have teeth under mutation, and edge probes behaved as documented. One scope gap is left for the human (first bullet).

- NEEDS-HUMAN [human] — **A hold before the last wave still ends the run at the next fold when the cause is a rewritten prerequisite.** Probe P1 (real git, the `StackFoldGit` shape: `A`,`Z` / `B` dep `A`, `W` dep `Z` / `V` dep `W`, with `fix/A` force-pushed after fold 0 and not restored): `B` is held and `W` is COMPLETE, but then `flow: wave 1 did not integrate (issue_A's branch origin/fix/A was rewritten …); STOPPING` (`template/src/pdca_harness/flow.py:3011`). `V`, which has nothing to do with `B`, stays PLANNED; holds `{'B': 'base'}`, rc 1. So for this cause the invariant "holds that bundle … and nothing else" only holds when the hold is in the last wave, or when the branch is restored before the next fold. The moved-base cause does the same (probe P4): `W` is built on its own base from the moved `main`, then the fold refuses `W`'s branch as "an undeclared cross-wave overlap; declare the conflict", though `W` never touched `a.txt`. That half is #739, which the brief puts out of scope. The rewrite half is #633's refusal at the fold, and no out-of-scope item in the brief names it. The limit is disclosed in `template/tests/test_flow_bundle_base_holds.py:13-20`, and every rewrite test is shaped to avoid it (last wave, or a restore before the fold). `B`'s hold line (`flow.py:1069-1071`) does not warn that the next fold will stop the run unless the branch is restored first. Decide whether to accept this, add that warning, or file a follow-up so the fold holds instead of stopping.
