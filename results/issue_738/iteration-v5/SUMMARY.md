## Findings

- NEEDS-HUMAN [impl] — **The "next fold stops the run" warning is printed when no fold follows.** `flow.py:2872` sets `fold_next=k < len(wave_list) - 1`. But when every bundle of wave k is held, `flow.py:2875-2876` (`if not runnable: continue`) skips that wave's fold, and the later waves hold only B's dependents, which are skipped. Failing case (real git, the test file's fixture): `A` in wave 0, `B` (`Depends on: A`) in wave 1, `C` (`Depends on: B`) in wave 2, `fix/A` force-pushed after wave 0's fold. Only one fold runs in the whole run, and the run's own end-of-run line then says "No fold of this run ran after the rewrite". The two lines contradict each other, which breaks the brief's rule that a hold line never promises more than the run does. Fix: set `fold_next` only when a later wave remains AND something of this wave is still left to build after the holds. Case (2c) still passes with that rule, since W is left in wave 1. Add this shape as a test.

- NEEDS-HUMAN [impl] — **A held bundle's cause is lost when a later base in the same wave hits a broken worktree.** `_bundle_bases` stores B in `held` and carries on (`flow.py:1051`). Fix: announce `failed` (with `fold_next=False`) in the `IntegrationTreeError` handler before the `STOPPING` line, and add this two-fault case.

- NEEDS-HUMAN [impl] — **`_LineBroken` is held per bundle, but the code base treats it as run-level next to `IntegrationTreeError`.** The patch re-raises only `IntegrationTreeError` (`flow.py:1048`; the handler at `flow.py:2868`). `_LineBroken` (the line checked out in the shared worktree could not be put back) subclasses `IntegrationError` directly (`integrate.py:110`). # Advisory code review — issue #738 (hold a bundle whose own base cannot be built)

Scope: correctness bugs the patch adds, plus reuse/simplification. Grounded on the patched tree at `$PDCA_TARGET`. The production change is small and matches the brief. The same goes for a later wave that `_runnable` empties (the `continue` at `flow.py:2813-2814`). Example: waves `{A}`, `{B: Depends on A}`, `{V}` (V not tied to B), with `fix/A` rewritten after wave 0's fold. Then add a case where B is alone in a non-last wave.
- `template/src/pdca_harness/flow.py:3033` (`holds.update({...: "base" ...})`) writes the literal `"base"`, while `cli._results_rc` matches it against `cli._BASE_HOLD` (`cli.py:699`, read at `cli.py:741`).
