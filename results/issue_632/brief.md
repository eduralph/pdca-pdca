- **Slug:** publish-raise-after-push-counts-as-pushed
- **Defect:** `flow._publish_bundle` (`template/src/pdca_harness/flow.py:642-665`) decides "this call pushed the branch" from `publish.json`'s mtime: True only if the record exists after the call and is new or changed (`flow.py:656-665`), and never when the call raised (`_isolate` returns None, `flow.py:661`). The new-PR path of `publish.publish` runs every git step, the push included (`git push --force-with-lease -u origin <branch>`, `template/src/pdca_harness/publish.py:319`, run at `:390-398`), then `gh pr create` (`publish.py:404-406`), and only then writes `publish.json` (`publish.py:431`). If `subprocess.run(pr_cmd)` RAISES after the push (e.g. `gh` is not installed: `FileNotFoundError`), no record is written. The bundle is treated as unpushed and goes into `held_unpushed`, and its dependents are skipped (`flow.py:2285-2291`), although its branch is on origin. That contradicts the stated rule: "A branch pushed this run is folded even if `gh pr create` failed after it" (`flow.py:2282-2283`). The rc-1 failure of `gh pr create` is already handled that way (`publish.py:407-414`, the record is still written with an empty `pr_url`, pinned by `test_publish_slice.py:359-381`). The raise is not, and the operator is not told the branch was pushed.
