- **Slug:** flow-carry-through-patchless-finished-bundles
- **Defect:** A re-issued stack-mode run (#646) decides what to carry, and what is "not clean", only from DIRECT plain `Depends on` edges onto a finished bundle that has a patch. A finished bundle with NO patch (a close / no-fix disposition, `N`) is not a fold candidate (`integrate._fold_candidates`, `integrate.py:240-248` on `c423f9d`), so any edge that runs through it is lost:
  (i) **missing work.** `N` (`Depends on: A`, no patch) and `D` (`Depends on: N`): `_carry_finished` builds its `dependents` map from direct edges onto fold candidates only (`flow.py:1254-1259`). `D` names only `N`, so nothing is carried, no line is seeded, `_closure_members` returns a seam for the edge to finished `N` (`flow.py:947-949`), `_point_at_integration` finds no line and clears the stack base (`flow.py:904-910`), and `D` is built on plain `main`, COMPLETE, without `A`. No hold, no warning.
  (ii) **unvetted work.** If `A` is not clean (e.g. its PR CLOSED), nothing holds `D`: `_runnable` holds a bundle only when a prerequisite it names DIRECTLY is in `held` (`flow.py:803-806`), and `N` never is. And `_cascade_not_clean` builds each id's prerequisites only from direct edges between fold candidates (`flow.py:1192-1197`), so a finished `P` (`Depends on: N`) whose branch was cut from a base holding `A` is judged clean and carried, bringing `A`'s closed-PR commit with it.
  The in-run closure walk #727 added already treats a bundle with no patch as a node ("one with no patch as one with a patch", `flow.py:924`). The carry does not.
