# Advisory code review — issue_728 (flow-carried-prerequisites-in-dependency-bases)

Lenses: correctness bugs the patch introduces, and reuse / simplification. Line numbers are on the patched target at `$PDCA_TARGET`. All gates pass (C4 red→green, T3 suites green).

## Findings

- NEEDS-HUMAN [impl] — A prerequisite reached only through a finished patchless bundle is never carried, so the dependent still ships without it, with no hold and no warning. `_carry_finished` picks what to carry from the drive set's *direct* plain `Depends on` edges, and only when the target is a fold candidate (`template/src/pdca_harness/flow.py:1269-1274`). A patchless `N` is not a fold candidate, so `A` behind it is never carried unless some other bundle names `A` directly. Then the walk in `_closure_members` leaves the graph at `A` (`flow.py:949`, `A` is not in `graph` built at `flow.py:986-988`), `D` gets no members, and `D` lands on the real base. `_runnable` does not hold `D` either: its only edge is to `N`, which is COMPLETE and not held (`flow.py:769-806`). I confirmed this with a probe on the new fixture (scratch copy, not committed): run `[A, N, D]`, `N Depends on A` closed with no patch, `D Depends on N` fails; re-issue driving `D` → no `flow: carried` line, `D` seen as `('', '')`, COMPLETE, and `fix/D` lacks `A`'s commit. This is criterion (2) with `W` removed. Only `W`'s direct edge makes the new test pass (`template/tests/test_flow_carried_prereq_bases.py:763-784`), so the test does not cover this path. The "missing-work" defect the brief targets is still reachable, and the docstring claim that dependents of an uncarried finished id "wait (`_runnable`)" (`flow.py:928-930`) is false here. Fix: either compute carry dependents through patchless finished nodes, or hold a bundle whose closure walk leaves the graph at a finished id that was not carried. This is probably pre-existing behaviour (before the patch, the seam fell back to a line the carry never seeded), but it breaks the invariant the brief restores ("a bundle with no patch is still a node in the graph its dependents' edges pass through"). If the human sees it as a follow-up, tag it [human].

- NEEDS-HUMAN [impl] — Changes outside the brief's list of restatements. The brief lists the expected restatements (`test_flow_resume_stack_prereqs.py` and `test_flow_merged_prereq_on_line.py:269`) and says "any change outside this list is a finding." The patch also renames and restates two tests in `template/tests/test_flow_dependency_scoped_bases.py:223-257`: `…keeps_the_line` → `…is_built_on_a_base_holding_it` / `…is_on_the_base`, with `_on_line` + `_has_all` replaced by `_own_base`. The change makes sense: both tests are about a dependent's base, and `_own_base` (`test_flow_dependency_scoped_bases.py:226-237`) still checks COMPLETE and every closure commit. So it is not weaker. It still needs a before/after entry in build-notes.md. I could not see build-notes.md, so I can't check whether it has one. The same `merged_prereq_on_line` file also changes `_built_on_own_base` callers at `:232`, `:240` and `:318`, beyond `:269`. Those swaps are like-for-like (they assert the same own-base shape the old `issue_W in seen` branch did), but they too should be listed.

## Checked and found clean

- Patchless finished nodes can never become members: `_fold_candidates` drops bundles with no patch (`template/src/pdca_harness/integrate.py:248`), so they never reach `mine` (`flow.py:994`).
- The `brief.md` guard for pre-#481 patchless parents (`flow.py:987`) is covered by `test_a_finished_bundle_with_no_brief_declares_no_edge_to_walk`.
- Member merge order (finished first, at wave -1, in the order asked for) cannot cause a false foreign-work stop. Ownership comes from each member's recorded cut point, not from merge order (`integrate.py:767-777`).
- `heads = {**carried, **carried_heads}` (`flow.py:989`) gives both the #633 rewrite check (`carried=`) and the naming of excluded bundles (`excluded=`). `excluded` only names and never decides (`integrate.py:778-779`), so passing carried non-members there is harmless.
- Dry-run is unaffected: `carry_took` stays empty in a stub run, and `own_bases` is off there (`flow.py:2636`).
- The restated suites still assert COMPLETE through their helpers (`test_flow_resume_stack_prereqs.py:199`, `test_flow_dependency_scoped_bases.py:236`), so the removed explicit `results[...] == COMPLETE` lines lose nothing.
- No duplicated logic. The patch reuses `_fold_candidates`, `build_bundle_base` and the existing refusals, and leaves `integrate.py` unchanged, as the brief expected.
