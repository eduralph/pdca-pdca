- NEEDS-HUMAN [impl] — `template/src/pdca_harness/flow.py:1042` — `_line_prs` names a line-cut PR only when the head the line had when that PR was cut equals the line's *current* head for the branch (`had.get(name) == took`). If a later fold took a newer, fast-forwarded head of the same branch (`carried_heads[name]` moves forward), a seam PR cut earlier drops out of the list. But it still holds the older head, and any rewrite that loses the newer head also loses the older one (the older head is an ancestor of the newer). So the #633/#695 messages can leave out a PR that needs a rebuild. Fix: list every pushed seam PR whose `had` has *any* head for `name` (`name in had`). The comment there says a stopped run "reported the rewrite a fold refused". That is true for a rewrite stop. It is not true for a base that fails for another reason (member merge clash, foreign work, refused push), where branches the earlier folds carried go unchecked at the end. This matches how a non-rewrite fold failure already behaves, so it is not a new class of gap, and the restated test `_stopped_at_b` (`test_integrate_carried_rewrite_late.py`) asserts this skip on purpose. Noted, not tagged.
- `template/src/pdca_harness/flow.py:937` (efficiency) — `_closure_members` calls `integrate._fold_candidates` over all of `built` (which reads each bundle's `publish.json` and target) once per runnable bundle, and `publish._resolve_target(d)` is resolved again at `flow.py:~1022` for each seam. Computing `cands`, `on_target` and `onto` once in `_bundle_bases` (`flow.py:1000`) and passing them in would remove an O(runnable × built) file-read loop. This is a small cost at today's batch sizes. A cleanup, not a bug.
- `template/src/pdca_harness/flow.py:2926` (wording nit) — the line's `unchecked` message adds `({'; '.join(cut…)) or 'none'})`. With no line-cut PRs it reads "rebuild … every PR this run cut from the line after it took that commit (none)". With some, it reads "(issue_S after issue_A's; …)". Both are understandable but clumsy. `_late_line_rewrite` (`integrate.py`) already splits the no-PR case into its own sentence, and the `unchecked` path could do the same.
