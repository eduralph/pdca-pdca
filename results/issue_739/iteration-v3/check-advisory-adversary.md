The 14th, `test_a_branch_that_also_clashes_with_the_base_itself_still_stops_the_run`, is the one meant to stop both before and after the fix. With the patch, all 22 tests in `test_flow_cross_wave_fold_holds` and `test_flow_same_wave_conflict` pass. This matches `gate-logs/C4-verify.log`. ## The fix: three concrete failing cases

- NEEDS-HUMAN [impl] — **The "stranded" check still blames a base move for an ordinary overlap when main has moved twice.** `template/src/pdca_harness/integrate.py:1870` sets `newer` if `head` holds *any* base commit the line's root lacks. `:1875-1877` then calls a partner stranded if it fails to merge onto the *current* `base_ref` in any file `head` also clashes with it in. Neither check asks whether the base commits `head` carries are what strand the partner. **Failing case (run):** take `test_a_bundle_built_before_the_base_moved_is_never_said_to_hold_the_move` exactly (nine-line `shared.txt`; A edits lines 2 and 8; Y, `Depends on: Q`, edits line 2; after Y publishes, main edits line 8) and add one unrelated main commit (`m.txt`) after the first fold, so Y's base is built on it. I checked the facts: A merges cleanly onto the base Y holds, and Y does not hold the line-8 commit. Output: `issue_Y held … issue_A's branch, already on the line, does not merge cleanly onto origin/main itself: origin/main moved since it was cut, and issue_Y was built on a newer origin/main than the line; its change also conflicts with issue_A's … To fold it, rebuild issue_A's branch on the new origin/main …`. Y's clash with A is only its own line-2 edit, so A's rebuild does nothing for Y. One unrelated commit on a busy main is enough to flip an outcome the suite pins as correct. Suggested fix: run the stranded trial on the base `head` actually holds (`git merge-base head base_ref`), not on the current tip of `base_ref`. Add this probe as a test.
- NEEDS-HUMAN [impl] — **The same root cause, the other way round: a base commit that main later undid is called the bundle's "own change".** `integrate.py:1875` judges against the current `base_ref`. If main has since undone the commit that strands the partner, the partner merges there, so it is not stranded and `:1880-1883` puts it in `own`. **Failing case (run):** A adds `a.txt`. After the first fold, main adds its own `a.txt`. Y (`Depends on: Q`, adds `y.txt` only) and V (`Depends on: W`, adds `v.txt` only) are built on that main. After Y publishes, main deletes `a.txt` again. Both Y and V are held with `its change conflicts with issue_A's, already on the line (conflicts in a.txt) … Proposed, for you to confirm: declare \`Conflicts with: A\``. U is skipped and the exit code is 1. Neither Y nor V touches `a.txt`, so the proposed `Conflicts with: A` is a permanent, wrong edit to the brief. The step that works is "update the branch from origin/main". This is rarer than the case above (it needs a revert on main), but the same fix applies: judge against the base `head` holds. Where the partner fails there but merges onto the current base, word a step for the held bundle ("update from the base").
- NEEDS-HUMAN [impl] — **"…which its branch does not hold" is false when the branch holds an older tip of the prerequisite.** `template/src/pdca_harness/flow.py:1584` treats every `own` partner that is a declared prerequisite as one the branch lacks, and `:1606-1607` says so. **Failing case (run):** Y (`Depends on: A`) is built on a base holding A. After Y publishes, A's owner pushes a fast-forward fixup to `fix/A` that touches Y's line. The fold takes A's new tip (allowed: commits pushed after a fold reach the line, `integrate.py:1329-1331`). Y is held with `issue_A is its own prerequisite, which its branch does not hold`. But `git log origin/fix/Y` shows `fix A` and `pdca-integrate: issue_A` in its history. The step ("rebuild issue_Y's branch on issue_A's") is right; the reason is wrong. Fix: check whether `head` holds any of the partner's commits and, if so, say it holds an older tip of the partner's branch.

But the brief's scope line no longer describes the change, and the two stranded findings above show those extra trials are still not right. A reviewer who checked "matches the brief's case-(3) rule" would pass them anyway.
