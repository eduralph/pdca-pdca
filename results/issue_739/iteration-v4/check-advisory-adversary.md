- NEEDS-HUMAN [impl] — **A prerequisite whose branch moved on is named as a partner it does not clash with.** `template/src/pdca_harness/integrate.py:2148` (`_rebuilt`) squashes `head` into one commit whose only parent is `start`. `_together` uses that from its second round, and from its first whenever `own` is non-empty (`integrate.py:1956`, called from `_held_on_line` at `:1899`). So everything `head` holds of a line bundle counts as `head`'s own change. When that bundle's branch has since moved on (a fast-forward fixup, which the fold takes, `integrate.py:1329-1331`), the old copy clashes with the new one in the trial, and the bundle gets named. **Failing case (run on the real-git fixture, through `flow._drive_and_act`):** base has a nine-line `shared.txt`. It never turns a stop into a hold, because the squash runs only once `own` is non-empty. Suggested fix: build the trial tip from `head`'s own change only. For example, before merging `head` in `_rebuilt`, also merge into `start` what `head` already holds of each `on` bundle (`git merge-base head <its head>`), so the old copy is on both sides. Add this probe as a test.
