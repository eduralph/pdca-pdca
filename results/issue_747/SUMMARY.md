## Reuse / simplification

- `template/src/pdca_harness/flow.py:1548-1553` (`_own_prereqs`): the flow reads each held bundle's brief again to split its partners into prerequisites and others. The fold already made that split (`integrate.py:1837`, `own`). The two agree as long as the brief does not change during the run. A long `pdca flow` can outlive brief edits, though, and then the fold-time line, the end-of-run line and the hold decision could disagree on which partner is "its own prerequisite". A simpler, drift-free option is to have `_held_by_line` return the prerequisite subset with the hold (or record it next to `held_out`), so the flow only formats it. This is minor and does not block.
- `template/src/pdca_harness/integrate.py:1980-2015` (`_trial(..., made=)`): an out-list parameter to get the final trial commit back works, but changing the return value would be simpler. It is small and local, and the out-list does keep every existing caller's tuple shape, so it is fine either way.
- Efficiency: on the conflict path only, each in-run fold conflict now runs `_built_on` over every bundle on the line, plus up to two `_partners` trials per bundle and up to two more for rule (e). Each trial checks out and resets the integration worktree. Before this patch the same path stopped the run, so nothing that used to pass is slower. On a large repo with a long line, one conflict could take a while. Not a defect.
