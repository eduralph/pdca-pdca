After the drop, D reached COMPLETE, built at the line's tip, and that tip does not have the squash commit. With a record that counts, the same setup holds D and says to delete the line on origin first (run as a control). Fix: when the run's line lacks the merge commit, have this hold line and the docs (`docs/07-crosscutting.md:916`) give the delete-the-line step too. Add this case as a test, because `test_stack_squash_merge.py:970` only covers a run with no older line.

Caching by `(p.name, repo, base)` would remove the repeats.
