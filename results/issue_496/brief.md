- **Invariant to restore:** Split adoption is an add-on to a run that is already producing results, so no failure inside it — a reschedule that cannot be computed, a child path that cannot be resolved — may end the run or lose the results of bundles the run has already driven. The failing part is named on stderr, its children are left in flight, and the run carries on and exits as it would have without the split. Source: the target's own rule, `flow.py:1087-1089` (`_reschedule` docstring), `flow.py:1095-1096` ("adoption is an enhancement, and no enhancement may take down a run that is already producing results"), and `flow.py:869-873` (`_real`: "Both callers refuse a `None`; neither ever raises"). This brief pins that rule with tests; it does not change it.
