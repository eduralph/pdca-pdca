# Adversarial review — issue 395 (same-wave conflict refused at accept)

Verdict: the fix holds for its main path. I found one concrete hole: the "tree" refusal can be bypassed. The red→green evidence is real.

- NEEDS-HUMAN [impl] — **The "tree" refusal can be bypassed with a tick while the integration checkout is still broken, so the bundle is accepted with no check and no message.** `template/src/pdca_harness/flow.py:333-335` turns an `IntegrationTreeError` / `_LineBroken` into a `"tree"` refusal. The row's own step (`flow.py:411`, `docs/07-crosscutting.md:763-764`) says "check that checkout …, then tick this row and accept again", which reads as *retry*. But `_refuse` returns False whenever an identical row is already ticked (`flow.py:366`). The tree row's text is the same on every attempt: the cause has no attempt-specific part (a stable SHA, worktree path and step). So if the tree is still broken when the human ticks and accepts again, the second trial fails the same way, the ticked row matches, and the accept goes through. Nothing is printed for it. That contradicts the docstring's "never accepted on a broken tree" (`flow.py:313`) and the docs' "refused whatever files it shares". **Reproduced** with a scratch probe on the bundle's own fixture. Pair 10/12 both change line 2 of `shared.txt`, and 20 depends on 10. I used the same fault as `test_a_check_that_breaks_the_tree_refuses_and_names_it` (12's apply fails, then the line will not check out again), but made it fire on every trial. 12's one extra session ticks the row and writes `accept`. Result: 12 is `COMPLETE`, `fix/12` is pushed, `gh pr create` is called once for 12, and then the fold holds it (`holds == {'12': 'conflict'}`). So two conflicting draft PRs are open, which is exactly what #395 is meant to prevent, and the human never chose an override. Stderr shows only the first "cannot accept" line. Suggested fix: for kind `"tree"`, refuse on every failed trial regardless of a ticked row (a tick there means "I fixed it, retry", not "publish anyway"). At minimum, print a line when a ticked row lets an accept through on a check that did not complete. Add a leg where the fault persists across the tick.
