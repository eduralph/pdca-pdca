## Motivation

Two real pdca-pdca batches (2026-07 and 2026-08-01) had same-wave bundles whose branches
conflicted, with no `Conflicts with` declared. Since #674 the fold holds one bundle and the
run goes on. That happens only after both were published, so two draft PRs conflict at merge
time and the held one's PR is work the human must close or redo. Five attempts to hold the
bundle after accept, without publishing it, each produced new bugs in the state that
created: accepted, with no PR. The human ruled that this state must not exist.

## Design

- The check runs at accept, inside the flow's sign-off. The C6 guard already lives there,
  every accept route goes through `_apply_decision`, and a refused accept is a state the
  driver already handles end to end. The sign-off session shows the row, and a re-run or a
  CSV re-run sees the bundle as in flight. It exits 1, as an unfinished bundle does. Its
  dependents are skipped as for any unfinished prerequisite, and a dry run calls no host.
- Whichever bundle is accepted first wins. The accepted set of a wave is then free of
  same-wave conflicts in the fold's order, so the fold has nothing to hold unless the human
  overrides (leg d).
- A refused accept behaves as a C6-refused one does today. Its decision file stays on disk, and the wave's later passes offer the bundle another session until the human picks iterate-plan, ticks the row, or the pass budget runs out (`_drive_wave`, flow.py:2516-2532). For a TRIAL refusal that would loop to the budget and then print the wrong hint ("raise [driver].max_passes"), so this change bounds it (leg h): after the refusal, B gets one more session; if the human records nothing new, the wave stops offering B, ends once its other bundles are terminal, and names the conflict step in its wave-end message. How Do marks "already offered once" is its choice (state it and test it), but it must live in the bundle's files (no hidden state) and must not change the plain C6 refusal path.
- The recovery step is existing machinery. Iterate-plan with `Conflicts with: <partner>`
  added, and the next run schedules the bundle after its partner, on a line that holds it.
- If the check cannot run, fail closed only where a conflict is possible: a textual
  conflict needs a shared path. This replaces iteration 5's "hold every sibling but the
  first".

## Alternatives considered

- **Hold after accept, with no PR** (iterations 1–5). Rejected: it creates the
  accepted-with-no-PR state, and every recovery path then needed new handling.
- **Publish anyway, and let the fold hold it** (`main` today). Leaves two conflicting PRs.
- **Footprint overlap only** (the advisory at flow.py:1586). A shared file is not proof of
  a conflict. Blocking on it would refuse bundles that merge cleanly. It is used only as
  the fallback when the real check cannot run.
- **Re-sequence automatically.** The best outcome, but it needs an unprompted rebuild on the
  line. That is a follow-up.

## Impact & compatibility

- A run with an undeclared same-wave conflict now exits 1 with one bundle AWAITING_SIGNOFF,
  instead of exiting 3 with a conflicting PR open.
- No config or brief-format change.
