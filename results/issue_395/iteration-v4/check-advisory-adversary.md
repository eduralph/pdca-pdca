- NEEDS-HUMAN [impl] — **A bundle that already has an open PR from an earlier attempt is held, and the run says it has no PR. That PR stays open, showing the rejected attempt.** `publish.json` survives an iterate (`template/src/pdca_harness/state.py:126-159` does not list it; the code says so itself at `template/src/pdca_harness/flow.py:2905-2906`). Then `flow.py:1697` prints "no branch pushed, no PR opened", `flow.py:1770` prints "opened no PR for it", and a re-issue's carry says "so it has no PR" (`flow.py:1396`). Probe `scratch/probes/probe_stale_pr.py`: run 1 publishes 11 alone (PR `…/pr/fix/11-11`, `shared.txt` = `eleven-v1`). 11 is then rebuilt as `eleven-v2`. Run 2 drives 10/11/12/20 and holds 11 for 10. Fix: when the bundle has a recorded `pr_url`, name that PR in these three messages and say it still shows the earlier attempt (close it, or leave it until the rebuild). Add a case for it.

- NEEDS-HUMAN [impl] — **Re-running the same batch after a trial hold calls the held bundle "already complete — nothing to run", suggests `rm -rf`, and exits 0.** The new carry advice (`flow.py:1549-1551`) only runs for finished ids that a bundle being driven depends on (`flow.py:1533`). Fix: in `_terminal_hint` (or the skip at `flow.py:3602-3606`), check `publish.read_conflict_hold(d)` and give the hold's step instead. Consider whether that re-run should exit non-zero.
