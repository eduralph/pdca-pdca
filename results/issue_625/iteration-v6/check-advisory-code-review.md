I found no correctness bug the patch introduces, and nothing needs a human decision from this lens. Notes:

- `tools/live/stack_mode_live.py:976-1013` — the fix does what the carry-forward asks. - `tools/live/stack_mode_live.py:725-727` vs `:997-1001` — small mismatch, no fix needed. `run`'s `synced()` skips an empty expected value (`not v or ...`), so with no recorded base tip or head it can write `synced: true`. `judge` then reports INCOMPLETE ("recorded no baseRefOid"). The result is right (INCOMPLETE, never PASS), but `observations.json` can show `synced: true` next to an INCOMPLETE. If you want the two to agree, `synced()` could return False when an expected value is empty.

I'm noting it so an INCOMPLETE E1b at sign-off is read as "raise `settle_max`" before anyone suspects the driver.
