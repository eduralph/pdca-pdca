# Result — issue 625 / stack-mode-live-github-check-tool

## 1. Spec (from brief.md)              ← Check verifies against THIS
- Defect / goal: A standalone tool in pdca-harness, `tools/live/stack_mode_live.py` (stdlib only), with five subcommands. `preflight` checks the token file, the repo guard, that the repo is private and pushable, and that merge commits and squash merges are both allowed, and writes nothing. `setup` runs `preflight`, then creates a run-scoped base branch `live-<UTC stamp>` from the sandbox's `main`, and prepares a local clone and bundle root holding the scenario's briefs. `run` drives the scenario through the real driver code, with the model leaves replaced by fixed patches (no model calls), real `git` and real `gh`. It merges PRs on the sandbox and records every observation as raw data in `observations.json`. `judge` reads `observations.json`, evaluates each named check, and writes `report.md` + `report.json` (one line per check: id, PASS/FAIL/INCOMPLETE, expected, observed). It exits 0 only if every check passes. `teardown` closes the run's open PRs and deletes the run's branches on the sandbox (`--keep` skips this). It never deletes the repo, never touches `main`, and never changes repo settings. `judge` needs no network, so it can be tested offline and re-run on a saved `observations.json`. **Departure from #625's wording:** #625 asks for "a disposable GitHub repo". This brief uses a persistent private sandbox instead, with a fresh `live-<stamp>` base branch per run as the disposable part (the token cannot create repos; see Alternatives). Merged/closed PRs stay in the sandbox's history. The human accepted this; the #625 closing comment must say so.

- `tools/live/stack_mode_live.py:725-727` vs `:997-1001` — small mismatch, no fix needed. `run`'s `synced()` skips an empty expected value (`not v or ...`), so with no recorded base tip or head it can write `synced: true`. `judge` then reports INCOMPLETE ("recorded no baseRefOid"). - `tools/live/stack_mode_live.py:1009` — once :993-1008 pass, the `synced` check only adds something for hand-edited files or an empty file list (`synced()` at :726 needs a non-empty list). Fine to keep as a cheap extra check. Not a bug.

- `tests/test_stack_mode_live_tool.py:308-360` — the new cases cover: reads agree but not synced (B and Q), a penultimate read on the old head, no recorded base tip, a timed-out poll on the old base, and old-base reads marked synced.
