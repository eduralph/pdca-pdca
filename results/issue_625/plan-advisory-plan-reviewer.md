- NEEDS-HUMAN — **E3 cannot FAIL, so a real driver bug would block accept instead of being filed.** The checks say `E3` requires "run 2: exit 0, no holds, D `COMPLETE`". But the PASS/FAIL/INCOMPLETE rule marks a check INCOMPLETE for "a driver run that raised or exited non-zero where the scenario needs it to finish". Criterion (7) bakes this in: "run 2 exited non-zero … the affected checks are INCOMPLETE, not FAIL". The hard sign-off condition then says "A run that ends INCOMPLETE blocks accept. A FAIL does not". Here is the problem case. Suppose GitHub's real `gh pr view` after merge + delete has no usable `headRefOid` (the very question #625 asks). Then `merged.merged_head` returns `None` (`merged.py:145-148`). `_gone_branch` raises at `integrate.py:1428-1432`, or `flow._finished_head` reports the id as not clean (`flow.py:1299-1303`), and run 2 exits non-zero. That is a driver/host mismatch, and the issue says it should be "filed as a bug". Under this plan it shows up as INCOMPLETE and stops the tool from being accepted. The brief needs to separate "the driver ran to the end and reported failure" (FAIL for E3) from "the run could not be observed" (INCOMPLETE: a refused merge or update-branch, a network error). Criterion (7) needs a matching case: run 2 exits non-zero with complete preconditions → `E3` FAIL.

- NEEDS-HUMAN — **No offline test checks that the destructive subcommands go through the guard.** The binding criteria (8)–(11) test the repo guard only through `preflight`. The Design says "every subcommand that writes to GitHub goes through it", and `teardown` deletes branches and closes PRs. Yet no criterion checks that `setup`/`run`/`teardown --repo eduralph/pdca-harness` (or a token-less run) exits non-zero without calling the fake `gh`. A build where `teardown` skips `preflight` passes every binding criterion. Live Validation would not catch it either, because it only runs against the sandbox. Add one criterion (fake `gh`, `teardown --repo eduralph/pdca-harness` → non-zero, `gh` never called), and ideally one that `teardown` never targets `main` (fake `gh` argv never contains `heads/main`). This guard is the only thing the AGENTS.md STOP exception relies on.

That blocks accept and costs a full live run plus teardown. The brief already knows one setting (`allow_update_branch = false`), so the same `gh api repos/<repo>` response can be read for `allow_merge_commit` / `allow_squash_merge`.
