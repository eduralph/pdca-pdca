- NEEDS-HUMAN — **"Keep the first of each conflicting pair" is under-specified when three or more bundles conflict, and the invariant overclaims.** Take A–B conflicting, B–C conflicting, A–C clean. A per-pair rule holds B because of A, then holds C because of B, even though B is already out. C is held for nothing, which breaks "Bundles that merge cleanly are never held" (brief line 17). Pairwise merges from a shared base also miss the case where each pair merges cleanly but merging them one after another onto the line conflicts. The fold would then still stop, which breaks "never the run". Fix: test each bundle against the bundles already *kept* (greedy, in fold order), not against every pair. Or narrow the invariant to what pairwise detection can actually guarantee. Add a 3-bundle chain case to the criterion either way.
