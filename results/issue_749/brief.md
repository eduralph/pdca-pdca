  **The frame (approved by the human).** For each file that git's real trial merge leaves conflicting, take exactly three line diffs, each run once and shared by both trials:
  - **the move:** `O` → `S`, where `O` is the merge base of the "before" trial's head merge (the head against the partner as it is on the line) and `S` is the base the head holds (`git merge-base head <remote>/main`, as today);
  - **the own change:** `S` → head;
  - **the partner's change:** `O` → the partner as it is on the line.
  Every diff runs with the algorithm git's merge uses in that repo, passed explicitly as `--diff-algorithm=<alg>`: the repo's `diff.algorithm` if set, else histogram (ort's default; `git diff`'s own unset default is myers, so the value must always be passed). It is read once per fold, as patched `integrate.py:1838-1846` already does. Also no indent heuristic, zero context and zero inter-hunk context, whatever the user's or repo's config says. Before use, each hunk drops the equal lines at its start and end (the same trim on every diff).
  - **"Before" trial positions:** the head side is the move and the own change chained (a line of `O` matches a head line when the move keeps it as a line of `S` and the own change keeps that line). A changed region whose old and new text come out equal is no change. The partner side is the partner's change.
  - **"After" trial positions:** the base is `S`. The head side is the own change. The partner side is the partner's change carried onto `S`: where it does not meet a move hunk it moves over unchanged; where it overlaps or touches one, the partner's version of that whole region wins (the same rule the rebuild uses, `wins=0`). It is not a fresh diff of `S` against the rebuilt commit.
  - **Conflict regions** are computed from these hunk lists with git's rule: hunks of the two sides that overlap or touch join into one region; a region with hunks from both sides is a conflict unless both sides give it the same text. Git's diff3 conflict markers are not read.
  - **Keys** (what of the head is at stake): each head line that a head-side hunk in a conflict region puts there, by its position in the head's file; and each line a head-side hunk in a conflict region removes, by where it came from: by its line number in `O` when the move kept it, else by the move hunk that brought it in. So the same removed line has the same key in both trials.
  - **Git still decides** whether each trial merge conflicts at all, and in which files (as `_trial` does today). The frame only decides the keys. A trial git merges cleanly has an empty stake. A file git's trial leaves conflicting where the frame finds no conflict region is not judged: it gets the named stop below, never an empty stake.
  - **The rule is unchanged:** the move is part of the clash exactly when the after-set is a strict subset of the before-set. Equal sets, or an after-set with a key the before-set lacks, are not judged: the run stops as today. The later checks (`_pinned` / `_explains` on the rebuilt line, the stranded / past split) stay, so a hold is still only advised when the named bundles' advised steps explain the whole clash.
  - **Not judged, named:** a conflicting file the frame cannot diff as lines (binary), or a trial with more than one merge base: the run stops, and the stop line names the file and says its conflict could not be judged line by line.
