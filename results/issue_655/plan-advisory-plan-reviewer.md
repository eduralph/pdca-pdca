- NEEDS-HUMAN — **The planned "is P on the line" test produces false holds for squash and rebase merges, and the success criterion cannot see it.** The brief has Do check that "the head a PR merged with" (`merged.merged_head`, `merged.py:114-143`, which returns `headRefOid`) is on the line through `integrate._carries`. After a squash or rebase merge, `headRefOid` is never an ancestor of `main`, so it is never on a line cut from `main` either. The harness already knows this: `integrate.py:504-505` says "a squash or rebase merge never puts it on the base either", and `integrate.py:533` says the same. So if P squash-merged into `main` *before* the run, the fresh line does hold P's change, yet the new check holds `D`. Today `D` builds correctly in that case, so this is a regression on a common repo setting. Criterion (3) covers only the "merge commit" case: the fixture's `_merge_pr` is `--no-ff` (`test_integrate_stack_bases.py:180-185`), so the RED/GREEN cannot detect this. The brief needs to either (a) specify a merge-strategy-independent test (for example, whether the line holds the base commit that the PR's merge produced or that existed when P read MERGED — fetch the base and check `<base_remote>/<base>` ancestry against the line tip), or (b) state in Scope that squash/rebase-merged prerequisites are held, fail-closed, with a hint, and add a criterion leg (4) that pins that behavior.

- NEEDS-HUMAN — **Which git clone answers "on the line" is unspecified, and lock scope is ignored.** `_runnable` (`flow.py:681-767`) does no git work today; it only reads bundle state and the `gh` PR state. `integrate._carries(wt, …)` (`integrate.py:539`) needs a worktree, and the only one is the integration worktree that `_fold_lines` uses under the integ lock (`flow.py:809-820`). The flow loop keeps only `folded_tips` and `integ` (branch names), not the worktree (`flow.py:2304-2307`). Do must therefore invent the plumbing: which repo, whether to fetch first, and whether to take the lock. That is review surface the brief leaves out. The brief should name the clone (for example `integrate.carry_view`, `integrate.py:185`, already used by `_carry_finished` at `flow.py:910`) and say whether a fetch or lock is required. It should also say what an unreadable clone means: hold, matching #647's fail-closed rule.

But the line is not always cut by this run. `_carry_finished` *continues origin's existing line* from a prior run's tip, and seeds `integ`/`folded_tips` before wave 0 (`flow.py:880-883`, `:943`).
