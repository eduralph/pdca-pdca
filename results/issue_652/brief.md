- **Slug:** carry-not-clean-cascades-across-finished-ids
- **Defect:** Before wave 0 a re-issued stack run carries its finished named ids onto the integration line (`flow._carry_finished`, `template/src/pdca_harness/flow.py:869-956`, called at `:2146-2149`). Each finished id is judged on its own: `_finished_head` (`flow.py:836-857`) checks only that id's PR state and head. A finished id that is not clean goes into `held` (`flow.py:947-956`), and `_runnable` then holds only the drive-set bundles whose plain `Depends on` names it (`flow.py:751-754`). Nothing looks at the edges BETWEEN finished ids. So when a finished `P` is not clean (e.g. its PR is CLOSED) and a finished `Q` was built on `P` (`Q`'s brief: `Depends on: P`, its branch cut from a line holding `P`) and is clean, `Q` is carried. `Q`'s branch carries `P`'s commits, so they come onto the line with it (the fold merges `Q`'s branch tip, `integrate._merge_published`, `template/src/pdca_harness/integrate.py:461-475`). A drive-set `D` with `Depends on: Q` is then built on a line holding `P`'s closed work, and nothing says so. #624's shape is the same gap one level up: `U` held → `D` finished before the run (`Depends on: U`) → `E` (`Depends on: D`) is built.

- **Invariant to restore:** The pre-wave carry never puts onto the line work it has judged not clean BEFORE the fold (from the PR state and head, `_finished_head`), directly or through another finished bundle's branch. A finished id is clean only if every finished id its plain `Depends on` names (transitively) is clean. Every bundle that would build on a not-clean finished id, directly or through others, is held and named, while the rest of the run goes on. Source: the harness's own carry contract, the first sentence of `docs/07-crosscutting.md:686-691` ("Only a clean prerequisite is carried"). A clean id carrying a not-clean id's commits defeats it.
