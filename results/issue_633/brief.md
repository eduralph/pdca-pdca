- **Slug:** fold-refuses-a-rewritten-carried-branch
- **Defect:** The stack fold carries each published PR branch onto the run's integration line by merging the branch's CURRENT tip (`integrate._merge_published`, `template/src/pdca_harness/integrate.py:461-485`). It skips a tip already in the line (`:472-473`) and otherwise merges it, so a fast-forward fixup reaches the line at the next fold (intended: `integrate.py:39-40`, `docs/07-crosscutting.md:665-666`). But `publish` force-pushes when a bundle is re-published (`git push --force-with-lease -u origin <branch>`, `template/src/pdca_harness/publish.py:312-319`; needed for #108). The single-step `pdca publish <id>` takes no drive claim (`template/src/pdca_harness/cli.py:487-488`; #573), so nothing stops it from running in another terminal while a flow run is live. When a bundle already folded this run is re-published that way, its branch is REWRITTEN. The old commits stay on the line, the new tip is not in the line, and the next fold merges it on top: duplicate or conflicting content on the line every later wave builds on, and no error.
