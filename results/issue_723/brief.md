- **Slug:** fold-builds-a-per-bundle-base
- **Defect:** `integrate.fold` can only fold onto the run's one line per target. It works out its destination itself from `integration_branch(cfg, base, batch)` (`template/src/pdca_harness/integrate.py:126`, used by `fold` at `:327` onward) and returns one entry per `(repo, base)` target. So there is no way to build a branch that carries exactly a chosen set of accepted bundles, which #463's dependency-scoped bases need (design: `results/issue_463/iteration-v1/brief.md`, Design §3).
- **Success criterion:** Real-git tests on the `StackFoldGit` fixture (`template/tests/test_integrate_stack_bases.py:123`), with branches published to the fixture's origin as that file's `_publish` helper does (`:150`), show the new `integrate.build_bundle_base` doing all of this:
  (1) **Exact contents.** Wave 0 = `A`, `Z` (unrelated, each with TWO commits on its own files). Fold the run's line with both. Then build `B`'s base from members `[A]`. The branch it pushes is on origin, contains every commit of `origin/main..fix/A`, contains no commit of `origin/main..fix/Z`, starts from `origin/main` as fetched, and the run's line branch and its recorded tip are unchanged by the build.
  (2) **Name.** The branch name is exactly `integration_branch(cfg, base, batch) + "-b" + _flatten_base(<id>)`, where `<id>` is the bundle id with any `issue_` prefix removed (for `B` = `issue_12` on the line `pdca-integration/main-r<key>` it is `pdca-integration/main-r<key>-b12`). `-b` never appears in `_flatten_base`'s output (it emits only `-h` / `-s`), so the name decodes to one (base, batch, id). The test asserts the exact name, that it has no `/` after `pdca-integration/` (never a ref-path prefix of, or under, the line or another base), and that ids `12`, `1-2`, `1/2` give three distinct names. `integration_branch` and `_flatten_base` (`integrate.py:126`, `:154`) stay unchanged.

Refused push: origin has `receive.denyNonFastForwards = true` and already holds the bundle's base branch at a commit that is not an ancestor of the new build (pushed there by the test); the build raises `integrate.IntegrationError` naming the branch and the remedy (delete it on origin, or allow force-pushes on `pdca-integration/*`).

A member that brings in a revert of earlier work (#623 / #673) raises: the test must make the revert check actually FIRE on a fresh-base build: adapt a #673 case from `test_integrate_revert_via_branch.py` (`:165`-`:236`) so an earlier member changes a path and a later member's branch brings in a removal of it that is not that member's own commit (the base must NOT already hold the earlier member's merge-and-revert, or the earlier member's merge is a no-op and nothing fires). A test that would still pass with the revert check skipped does not count; if Do finds no case can fire on a fresh base, it says so in `build-notes.md` with the reason instead of shipping a test that cannot go red.
  (5) **Rewritten carried member (#633).** Given a recorded head for a member, a member whose branch on origin no longer has that head raises `IntegrationError` naming the rewrite. Nothing is pushed.
  (6) **No foreign work (ownership by recorded cut point).** Definitions: a member's *cut point* is its recorded `stack-base-tip` (`publish.read_stack_base_tip`, `publish.py:690`) when it has a `stack-base` record (`publish.read_stack_base`, `publish.py:679`, non-empty), and nothing extra otherwise — but "nothing extra" is trusted only for a member that was never stacked (see the fail-closed list). A member's *own work* is the non-merge commits reachable from the head the build merges for it and from neither the fetched `<remote>/<base>` nor its cut point. Rule: after all members are merged, every non-merge commit on the result that is not reachable from the fetched base must be some member's own work; otherwise the build raises `IntegrationError` and pushes nothing. The message names the commit, the first member (in member order) whose head reaches it, and each `excluded` bundle whose head reaches it — or says no bundle of the run owns it.
