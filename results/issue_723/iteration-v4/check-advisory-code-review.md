- NEEDS-HUMAN [impl] — `template/src/pdca_harness/integrate.py:967-971`: the "harness branches are no bundle's" fence (`lines`) takes the first-parent chain of **every** ref under `refs/remotes/origin/pdca-integration/`, limited only by `--not <base_ref>`. Two problems. (a) Too wide: another target's line (say `pdca-integration/develop-r…`) has a first-parent chain that, measured against `origin/main`, holds that other base's own non-merge commits. Those commits go into the fence, so `_own_commits` skips them for members and for excluded bundles alike. A foreign commit reached only through them is never counted as anyone's work, so the build lets it through quietly, when it should refuse (brief criterion 6: "refused, never silently widened"). This is an edge case (a member built on another target's history), but the fix is cheap. (b) Cost: per-bundle bases are never deleted (the brief leaves that for later), so this `rev-list` walks a set of refs that keeps growing on every build. Scoping the glob to this target's stem, `refs/remotes/origin/pdca-integration/<_flatten_base(base)>`, fixes both. That stem is the prefix of `integration_branch(cfg, base, …)` and of every `bundle_base_branch` for this target. Add a test where a second target's line exists on origin.
